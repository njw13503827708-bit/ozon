# Ozon 整批上传确认

## 操作流程

```text
运行批次 → 等待全部商品生成与质检 → 审阅整批上传 →
若阻断则返回工作台修改 → 重新生成 → 确认整批上传 → 查看多店提交结果
```

整批确认是唯一真实提交入口。确认页只读，只显示整批商品、SKU、店铺、价格、图片、属性覆盖率和风险；发现问题后使用“返回工作台”定位商品并修改，不能在确认页绕过校验。

## 整批阻断规则

以下任一情况都会阻止整个批次确认：

- 商品仍是测试/占位标题、SKU 或 offer 标识；
- 俄文标题、描述、卖点、搜索标签或富内容缺失，或对应字段仍是中文；
- Ozon 类目没有锁定为用户最终选择，或锁定选择与 Ozon API 类目资料不一致；确认页会显示中文来源标题、俄文标题、最终类目名称与路径，跨语言语义由操作员在整批一次确认时核对；
- 必填属性、商品/包装长宽高、重量、价格、SKU 或目标店铺不完整；
- 最终上传草稿少于两张商品图、与已通过质检的图片集合不一致、图片文件缺失，或技术优化/图片质检未通过；
- 草稿含库存、仓库或数量字段；
- 任一商品未完成、失败、未审阅，或整批成员与采集箱不一致。

所有商品都通过后，操作员只确认一次整批上传。批准记录绑定批次成员、店铺、文案、类目、属性、规格、价格、图片内容及店铺 offer；之后任何受保护内容变化都会使授权失效，必须重新审阅和确认。

## 提交与重试

每个店铺在实际写入前都会再次检查授权和当前整批哈希。已有成功、处理中或 Ozon `task_id` 的店铺不会重复创建；只有明确失败且内容哈希未变化的店铺可以安全重试。出现不明确结果时整批保持阻断，先回工作台查看，不要重复点击上传。

## 离线自检

```powershell
$env:PYTHONUTF8='1'
.\.venv\Scripts\python.exe scripts\project_self_check.py
```

自检包含 `batch_upload_gate` 和 `batch_authorization_integrity`。真实提交前要求该默认离线自检为 `PASS`，并确认 `ozon_write_api_calls` 与 `inventory_api_calls` 都为 0。自检不访问 Ozon，也不打印店铺凭证。`--full-tests` 仅用于诊断导入项目中尚未修复的 Windows 兼容基线；当前结果会失败，不作为上传确认条件。

店铺凭证只保存在本机配置中；导出和交付包必须排除凭证、日志、运行 PID、缓存、临时商品、`.venv` 和 `node_modules`。
